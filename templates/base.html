This repository's Dockerfile/compose stack has no Node.js runtime dependency at all (Python/uv only); adding a Tailwind CLI/PostCSS build step would newly require Node.js to *build* the image, which is a real, avoidable increase in required tooling for a project whose zero-cost/zero-Node posture has held since Phase 0. Putting these in Tailwind's `base` layer (rather than plain CSS) means any element-level utility class used directly in a template (e.g. nav.html's `text-white`) still wins the cascade, per Tailwind's documented layer-precedence order (base < components < utilities) — these are *defaults* a template can always override, not a competing styling system.
